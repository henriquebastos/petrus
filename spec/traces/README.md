# Impetus golden trace corpus

This directory is the deterministic, language-neutral conformance corpus for
ratified Impetus behavior. Every fixture is generated by the public Python
reference binding and replays without private repositories, the legacy Petrus
oracle, or external evidence.

## Generate

From this repository root:

```sh
UV_FROZEN=1 uv run python scripts/gen-golden-traces.py spec/traces
```

Generation writes sorted, indented UTF-8 JSON with one terminal newline. The
manifest records each fixture's SHA-256. There are no timestamps, random
identities, environment-dependent paths, or source-repository commits in the
bytes. Two runs from the same source must be byte-identical.

## Corpus format

Each `petrus-impetus-golden-trace` version-2 document contains:

- `net`: a complete canonical Net-definition v3 document;
- `bindings`: language-neutral descriptions of every named guard or handler;
- `initialMarking`: ordered queues of `{color, data}` tokens by place;
- `walk`: explicit actions and the candidates, firing outcome, marking, and
  status observed at every boundary;
- `history`: the complete canonical schema-5 History record sequence; and
- `final`: the final marking and derived status.

Every token is exactly one `{color, data}` value. A black token has `color:
null` and `data: null`; aggregate data remains the data of one color. The
format has no representation for the legacy oracle's multi-part merged token.

Actions are deterministic `step`, identified `deliver`, or `seal` operations
with explicit logical instants. Candidate entries preserve transition order,
per-input-arc selections, and token queue order. Produced entries are recorded
per destination, not as one firing-wide token.

## Normative coverage

| fixture | ratified behavior |
|---|---|
| `passthrough_chain` | deterministic black-token passthrough |
| `fifo_queue` | token queues and FIFO default selection |
| `inhibitor_arc` | inhibitor gating |
| `conflict_selection` | deterministic conservative conflict selection |
| `per_arc_passthrough` | weight-two consumption, read accounting without forwarding, and each consumed token routed independently through each output arc |
| `guard_enumeration` | guards evaluated per binding; a failed FIFO-head binding does not mask a deeper satisfying binding |
| `source_delivery` | scheduler-excluded source delivery, stable delivery identity, registration lifecycle, and `ExternalEventDelivered` before projection |
| `heterogeneous_fanout` | positive per-arc fan-out with a different single-color token on each branch |

The replay test enumerates the manifest rather than a compatibility subset, so
every listed fixture is normative and must pass:

```sh
UV_FROZEN=1 uv run pytest -q tests/petrus/impetus/petrinet/test_golden_replay.py
```

## Compatibility

Conformance is defined by the current fixtures and the public reference
implementation. No compatibility with previous fixture formats is promised.
