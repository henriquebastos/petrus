# Observation protocol version 1

This document, `observation/engine-snapshot-v1.json`, and
`observation/engine-history-page-v1.json` are the
language-neutral, read-only producer contract for observing one live Petrus
Engine. The fixture is generated by the Python reference producer and a test
requires exact structural equality; consumers must not infer fields from a
hand-authored example.

The live snapshot and History cursor remain runtime transports. For portable
offline use, the producer can materialize its current definition and complete
History prefix as the one [Petrus Net document](net-document-v1.md) format.

Every response is strict JSON and numbers must be finite. Snapshot and History
responses start with integer `protocol: 1` and the canonical `instance`
identity. The document response starts with `format: "petrus-net-document"`
and integer `version: 1`. Mutable values are detached from producer state.

## Snapshot

A snapshot contains `definition`, `frontier`, and `current`. `frontier` is the
exclusive canonical History length captured atomically with current state.
The definition has `name`, exact `time_domain: "integer"`, lexically path-sorted
`places` and `transitions`, authored-order `arcs`, and `completion`. Arcs carry
their zero-based authored `position`, so duplicate endpoints remain distinct.
Resolved arc colors are emitted.

Declarations use `kind` as their discriminator: `symbol` adds `name`, `cel`
adds `expression`, and `anonymous` adds neither. `null` means absent and is not
anonymous. Handler and guard declarations include their canonical `uri`.
Anonymous display names and executable implementations never cross the
protocol. Timers preserve authored order and use `kind: delay` with integer
`duration`, or `kind: until` with integer `instant`.

`current` contains sparse place-sorted `marking` with FIFO `{color, data}`
tokens; `status`; integer `watermark`; ordered `in_flight`; source/key-sorted
`armed`; and integer-or-null `next_maturation`. An in-flight occurrence has
its transition, binding selections, invocation/result, and exactly one phase:
`pure_pending`, `activity_pending`, or `projection_pending`.

Protocol-v1 `current` does not add an `active_scopes` projection. A scope-aware
consumer derives active generations by folding the complete canonical History
prefix through `frontier`; it must not infer them from token values or select a
generation by name alone.

Snapshot status is current-only and may evaluate the current pure completion
declaration. Authoritative historical status and enabledness are unavailable;
neither may be inferred by re-executing historical declarations.

## History pages and cursors

`after` is an exclusive confirmed prefix length and `limit` is a positive
integer. A page returns dense zero-based positions in `[after, next)`, where
`next = min(after + limit, frontier)`. The first request uses zero; reconnect
uses the last confirmed `next`; `after == frontier` is an empty page. Negative,
boolean, non-integer, future cursors and non-positive/boolean/non-integer limits
are refused, never clamped. Each nested `record` is the unchanged canonical
History schema-5 encoding. The enclosing observation protocol remains version
1; record schema and protocol version are independent.

A cursor inside one append batch is an explanatory record prefix, not a claim
that the prefix was an externally observable atomic runtime state. Historical
consumers fold record projections only: they do not invoke handlers,
Activities, guards, filters, completions, or obsolete code, and they must not
label a folded prefix as authoritative historical status or enabledness.

## Standard-library HTTP transport profile

The Python producer supplies a subordinate transport binding in
`petrus.engine.observation_http`. It does not change the semantic protocol
above. `create_observation_server(engine, host, port)` binds a
`ThreadingHTTPServer` to one Engine but starts no thread: the application owns
`serve_forever`, shutdown, `server_close`, and process/thread supervision.
Closing the server never closes its Engine.

`GET /v1/snapshot` returns the snapshot. `GET /v1/history?after=<int>&limit=<int>`
returns one History page. `GET /v1/document` atomically materializes the same
Engine as one Net document: one `observed` Timeline entry per canonical History
record, a complete marking on every entry, the record in non-authoritative
`metadata.history_record`, and the final current observation in the head
entry's metadata. The document route takes no query.

Both History query fields are required exactly once; unknown, duplicate,
empty, signed, whitespace, and non-ASCII-decimal forms receive 400. Semantic
cursor/limit refusal also receives 400. This adapter additionally refuses
`limit > 1000` rather than silently clamping it.

Unknown routes receive 404. Methods other than GET and OPTIONS receive 405 and
cannot reach Engine. OPTIONS supports browser preflight. Under the trusted
watcher premise every response allows origin `*`, methods `GET, OPTIONS`, and
header `Content-Type`; credentials are not supported.

JSON uses deterministic compact UTF-8 encoding, `application/json`, an exact
`Content-Length`, and `Cache-Control: no-store`. Errors have the strict shape
`{"error":{"code":"...","message":"..."}}`: query/protocol `ValueError` is
400, closed or poisoned Engine `RuntimeError` is 503, and unexpected failures
are generic 500 responses without exception details. A disconnected requester
does not affect Engine execution.
