# Joined initial-creation transaction replay

## What changed

Added paired real Absurd/PostgreSQL profiles at the initial Engine-construction
transaction boundary. The profile's opaque process generation can exist before
an Engine, so the authored `engine.create` operation still crosses the one
normalized World interpreter and calls only the public `create_engine` door.

The refusal profile lets production prepare `InstanceCreated` and the initial
`TokensInitialized`, then refuses the PostgreSQL transaction before acceptance.
Detached History remains empty. After abrupt drop, fresh profile load observes
that absence and the same normalized command creates the supplied identity and
marking exactly once.

The acknowledgement-loss profile commits the two-record creation batch, then
raises before `create_engine` can return an Engine. Fresh public `load_engine`
reconstructs the accepted identity and initial token without another creation
transaction. One independent checker derives authority from accepted/refused
transaction attempts and detached PostgreSQL History. Mutation tests reject a
phantom instance after rollback, acknowledgement loss without accepted truth,
and accepted truth which fails to reconstruct on fresh load.

## Why it matters

`instance_created` is the first named durable History cut. The pair now proves
both outcomes at the real joined provider boundary: rollback cannot expose a
partial identity or marking, while accepted-but-unacknowledged construction is
recoverable through public load without duplicate initialization.

## Review and follow-up

The change is test-owned and adds no production API. The profile keeps its
maybe-present Engine inside the opaque generation; Timeline and checkers see
only detached strict data. Graceful close and abrupt drop remain separate.
Artifact v1-v4 identities and retained fixtures are unchanged. A separate
module keeps initial-construction composition out of the already large joined
activity/lifecycle profile without creating another scheduler or replay path.
No debt item or decision record is needed.

CV19.DS2 remains Active. This qualifies the supplied-identity creation batch
for the public Absurd/PostgreSQL composition only; database power loss,
autogenerated identity construction, and the broader provider/fault matrix
remain unclaimed.
