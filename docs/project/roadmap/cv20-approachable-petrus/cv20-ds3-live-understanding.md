# CV20.DS3 — Live understanding

## Intent

Give a person one coherent way to arrange and understand a Net before motion,
inspect observed or simulated evolution, and explore a protected hypothetical
branch. Petrus owns portable semantics and provenance; Arx owns interactive
presentation and file custody; neither enters Engine execution authority.

## Scope

- Deliver a strict Petrus-owned portable document with one exact canonical Net
  definition, optional portable view, and optional forkable execution lineage.
- Preserve ES-061's dense sequential integer ids, explicit smaller parents,
  explicit `observed`/`simulated`/`manual` provenance, one common History-record
  fact, manual intervention facts, and immutable evidence custody anchors.
- Keep view outside canonical Net identity and execution lineage.
- Define strict parse, validation, projection, serialization, conformance
  fixtures, source-anchor custody, and source-format admission boundaries.
- Hand the accepted contract to Arx for shared-canvas zoom, pan, arrangement,
  timeline navigation, inspection, “Explore from here,” Save As, and reopen.
- Join canonical semantic state with correlated best-effort operational progress
  only after DS1 supplies a concrete live consumer; listeners never block motion.

## Delivery sequence

- **Done:**
  [CV20.DS3.TS1 — Portable definition and view document foundation](cv20-ds3-live-understanding/cv20-ds3-ts1-portable-definition-view/index.md)
  owns strict envelope, definition identity, node-position view, projection,
  owner fixtures, and the contract Arx consumed for the static V5 route.
- **Next Petrus substrate:** forkable lineage validation, evidence-source
  custody, projection, and conformance fixtures from ES-061's accepted model.
- **US1 — Arrange Hamsterdan V5 in Arx.** Open the real 108-place,
  137-transition, 570-arc V5 Net on the shared canvas; zoom, pan, move, save,
  close, and reopen without changing definition identity.
- **US2 — Inspect and fork protected evidence.** Navigate one uniform lineage,
  open an observed point read-only, create a manual/simulated branch through
  Save As, and retain a later observed sibling without rewriting production
  evidence.
- **TS2 — Application-bound V5 fork.** Use Hamsterdan-owned bindings or an
  accepted capable profile for the large simulation case rather than
  relabeling Arx-local token manipulation as Petrus execution.

## Acceptance / Done condition

1. Definition-only, arranged, observed, simulated, manual, and mixed-fork
   documents use one strict envelope and one navigation entry model.
2. Exact source relation, definition identity, ids, parents, head, provenance,
   checkpoints, and malformed/confused inputs are mechanically verified.
3. Arx opens the exact Hamsterdan V5 definition on its shared canvas and its
   node arrangement survives save/close/reopen with unchanged definition bytes.
4. An observed capture remains protected; exploration creates a distinct
   document and cannot be presented or exported as original observed truth.
5. One consumer loop navigates observed records, manual intervention, simulated
   records, and an observed sibling without opening nested source timelines.
6. Live semantic and operational presentation preserves provenance and cannot
   delay, authorize, or mutate Engine motion.

## Driver QA and evidence plan

- Promote ES-061's exploration fixtures into normative protocol/conformance
  tests only after the protocol spelling is selected.
- Run strict positive/negative round trips and source-custody mutation tests.
- Execute the real V5 Arx interaction route and inspect save/reopen artifacts.
- Execute one producer-backed capture-to-hypothesis fork and, separately, the
  Hamsterdan application-bound large case.
- Run Petrus and Arx focused/full gates at their respective boundaries.

## Out of scope

- Changing one Instance's canonical linear History into a branch graph.
- Treating SHA-256 as producer authenticity or a signature.
- Making every inspectable point resumable.
- Giving Arx credentials, provider clients, History writer authority, or host
  lifecycle ownership.
- Settling source attachment or large-file storage without measured evidence.
