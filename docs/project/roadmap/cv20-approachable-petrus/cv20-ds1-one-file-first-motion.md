# CV20.DS1 — One-file first motion

## Intent

Let one readable flow/application file compile, validate, create or resume an
identified Instance under an honestly named local profile, reach representative
motion, and report canonical and operational evidence without requiring the
developer to assemble every Petrus component before first feedback.

## Scope

- Execute AX28 first against the current public runtime and retain an exact gap
  map rather than designing a facade from recollection.
- Decide the thin runner owner, local durability profile, state location,
  process lifetime, and terminal/awaiting behavior.
- Compose existing DSL, canonical definition and inspection, History Store,
  Dispatch, Engine, driving, observation, replay, and resume contracts.
- Keep every constituent replaceable through the existing lower-level APIs.
- Prove one zero-agent vertical route before adding agent convenience.

## Candidate story seeds

- **TS1 — AX28 first-motion gap map and profile decision.** Execute the frozen
  route, identify only missing generic composition, and settle the named local
  profile and runner lifetime.
- **US1 — Compile, inspect, and reach first motion.** A developer runs one
  flow/application source and receives actionable validation plus inspectable
  canonical artifacts and observed motion.
- **US2 — Resume and explain local state.** The same source resumes the named
  Instance under the declared durability guarantee and reports where its state
  and artifacts live.

## Acceptance / Done condition

1. **Given** one readable flow/application file, **when** the developer invokes
   the selected entry point, **then** Petrus compiles and validates before
   motion and reports the canonical definition and inspection artifacts.
2. **Given** the named flagship local profile, **when** an Instance starts or
   resumes, **then** the command states its durability, state location, and
   lifecycle rather than hiding them behind “local.”
3. **Given** representative ingress and deterministic work, **when** the runner
   advances, **then** the developer sees the identified Instance, accepted
   History facts, current state, required wait, and final or bounded disposition.
4. **Given** restart under a durable profile, **when** the same Instance resumes,
   **then** canonical replay and state agree without relying on a Python frame.
5. **Given** an advanced application, **when** it descends to the existing
   Engine, store, Dispatch, Worker, or host seams, **then** no process semantic
   or artifact format changes.

## Driver QA and evidence plan

- Record the exact AX28 source, commands, concepts, artifacts, and steps to
  first observed motion before changing production code.
- Exercise compile refusal, missing bindings, fresh start, representative
  ingress, terminal or awaiting exit, restart, replay, and resume.
- Verify canonical artifacts byte-for-byte and compare live state with replay.
- Run focused tests, the complete repository gate, and one documented fresh
  checkout behavior route.

## Out of scope

- Selecting the full expressive authoring vocabulary owned by DS2.
- Arx layout and forked document interaction owned by DS3.
- Generated package authoring owned by DS4.
- Agent-specific convenience owned by DS5.
- A supervisor that takes over the application's deployment lifecycle.
