# Project Briefing

This directory holds concise current context that should not be re-explained in every agent session.

Read this index first, then the focused documents relevant to the work:

- [Identity and purpose](identity-and-purpose.md) — what the project is, whom it serves, and its product premises.
- [Glossary](../glossary/index.md) — accepted project-specific terms and the boundaries between them. Read it when domain language affects the task; do not preload unrelated specifications or records.
- [Current state](current-state.md) — what works now, what is incomplete, and what matters next.
- [Constraints and environment](constraints-and-environment.md) — durable architecture premises, operating environment, boundaries, and hard constraints.

Keep current truth in these documents. Store each accepted domain definition once in `docs/project/glossary/` and link to it from other records. Put consequential architectural or product rationale in `docs/project/decisions/records/` and ordinary textual history in Git. Keep commands and development policy in `docs/process/development-guide/` rather than duplicating them here.
