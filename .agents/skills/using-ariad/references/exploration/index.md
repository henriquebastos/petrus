# Exploration

Exploration is the Ariad work area for material that is real enough to preserve, but not yet formed enough to become delivery or refinement.

Delivery asks: what are we delivering?

Refinement asks: what existing capability needs care?

Exploration asks: what is being captured, and what is it becoming?

This area is part of the core method. It defines how Ariad preserves and thickens exploratory material before delivery commitment or refinement care. The visual language can support that work, but the concepts and the visuals live in separate layers.

## Why this exists

Ariad has a strong model for bounded delivery through stories, checkpoints, validation, review, coherence, and history. That model works when the work has enough shape to become a commitment.

Some work appears earlier than that. A new idea appears and needs to be worked through. A promising direction reveals itself in the product. A bug is noticed but not understood. A repeated tension appears across sessions. A product discomfort keeps returning. A methodological gap is felt before there is a proposal. If this material goes directly into the roadmap, the roadmap becomes noisy. If it stays only in memory or conversation, it can disappear.

Exploration holds that earlier territory. It treats exploratory work as narrative thickening: thin signals are captured, related material accumulates, clusters and resonance appear, attractors may form, and some Exploratory Stories eventually become candidates for Delivery, requested changes for Refinement, or archive material.

## Language boundary

Ariad distinguishes **Exploration**, **Delivery**, and **Refinement** as methodological work areas.

A runtime may implement those areas as modes or lanes. Maestro may speak of **Exploratory Mode** because it executes exploration inside Mirror Mind and renders its state through concrete surfaces. Ariad's method language should prefer Exploration, Exploratory Work, Delivery, Delivery Work, Refinement, and Refinement Work.

## Layer separation

Ariad separates three layers for this work:

```text
Ariad Exploration
  conceptual model, events, transitions, criteria, exploratory moves

Runtime exploratory mode
  execution of exploration inside a specific agentic runtime

Visual grammar
  rendering of exploratory state and relationships
```

The visual grammar may use shapes, colors, boards, flows, or other components. Those choices are renderings, not method contracts. A signal remains a signal whether it appears as a triangle in a terminal, a card in a web surface, a line in an API response, or a spoken suggestion in conversation.

## Current surfaces

Maestro currently uses four surface names for exploratory work:

```text
Signal Radar
  What is being picked up?

Narrative Field
  What is thickening across active Exploratory Stories?

Exploratory Story View
  What is happening inside this story?

Candidate Gate
  What is ready to cross?
```

These surfaces are introduced in [Exploratory Flow](flow.md) and detailed in [Visual Grammar](visual-grammar.md#core-exploratory-surfaces).
